CDI · real-estate due diligence · architecture contract

Deep Research Module

One Markdown fact sheet becomes eight property missions, eight sequential domain-scoped STORM investigations and one property synthesis.

Deep Agents 0.7.7 · gpt-5.6-luna · Layer 2 maximum reasoning · Layer 3 low reasoning

01Purpose

CDI separates supplied property facts from public research. Layer 2 transcribes and routes the supplied evidence. Layer 3 investigates what remains, retains the public sources, tests the conclusions and creates one property-level answer.

All eight domains run for every property. The geopolitical and supply-chain domain performs a dependency assessment even when its final result is that no material pathway was established.

02End-to-end flow

Each coordinator completes its domain before the next begins. Its final assistant response is saved verbatim; synthesis runs with every available domain response.

03Layer 2 — eight missions

Independent JSON-object calls receive recursively split Markdown chunks and the planner snapshot. Available results are appended in source order into eight domain missions.

{
  "agent": "exact domain name",
  "mission": "property-specific research objective",
  "context": [
    {"section": "heading", "fact": "evidence", "means": "interpretation"}
  ]
}

Python splits, schedules and serializes any returned JSON object. It does not enforce a response schema, semantically verify, repair or deduplicate the model's routing. One failed chunk does not block available results.

06Domain-scoped STORM method

  1. Practitioner: tests operational reality, sequence, feasibility, cost and downtime.
  2. Academic: tests authorities, standards, rigorous research and evidence quality.
  3. Skeptic: tests adverse evidence, failure modes and alternative explanations.
  4. Economist: tests cash flow, cost, financing, value and exit consequences.
  5. Historian: tests precedent, time series, comparability and regime change.
The five lenses are independent subagents. Their agreement is not independent confirmation because they use the same model and runtime. The coordinator must preserve material disagreement and submit cited claim clusters to the verifier.

07Evidence and search

Lens and verifier subagents research through candidate search results and retained pages. Snippets support discovery, while report claims use opened sources and direct Markdown links. The run-scoped cache reuses an identical query or fetched URL without sharing conclusions.

Python enforces the trust boundary: HTTP(S)-only public destinations, redirect revalidation, fetch timeout and size limit, retained raw bytes, canonical text, hashes and attribution. Search results and web pages remain untrusted data. Citation accuracy is evaluated by the citation-verifier subagents, not by Python content grading.

search_web(query) → candidates with snippets
read_source(url)  → retained bytes + canonical text + source ID

08Memory and resume

Eight stable coordinator threads and one synthesis thread share a run-local SQLite checkpointer. Each coordinator's messages and lens/verifier task results remain durable in its thread checkpoint; Python does not require a model-written artifact tree.

  • Resume a pending graph with the same thread and ainvoke(None).
  • Commit a completed checkpoint without another model call.
  • Resume failed work in the same checkpoint thread with -RetryFailed.
  • Start a fresh synthesis thread only when recovered domain input changes.
  • Retain the run-scoped source cache across retries.
  • A crash during an unfinished synchronous task batch may replay that batch.

11Optional operational report

  • The run metadata uses the current schema.
  • Each domain invocation has a terminal execution record.
  • Available domain responses and the synthesis response were saved.

This report is manual and observational. It never grades Markdown, changes run status, blocks synthesis, or triggers a content-repair call.

12Operation

.\run.ps1 -FactSheet 'C:\path\fact_sheet.md'
.\run.ps1 -Resume '.\runs\L2_YYYYMMDD_xxxx'
.\run.ps1 -Research '.\runs\L2_YYYYMMDD_xxxx' -Online -PublicInputConfirmed
.\run.ps1 -ResumeL3 '.\runs\L3_YYYYMMDD_xxxx'
.\run.ps1 -ResumeL3 '.\runs\L3_YYYYMMDD_xxxx' -RetryFailed

The API key lives only in .env. Public-input confirmation is required before Layer 3 sends queries externally. Layer 3 currently uses low reasoning for every model and web-search proxy call; this is configuration for measured live testing, not a CLI mode.

CDI architecture · current domain-scoped STORM contract · offline structural validation is reported separately from an explicitly authorized live research run.
